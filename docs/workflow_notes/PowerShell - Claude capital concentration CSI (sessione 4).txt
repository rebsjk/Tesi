# Index weight construction

Status: **decided** (2026-08-19).

## The gap this resolves

The official point-in-time S&P 500 constituent weight (as pu
blished by
S&P and mirrored in CRSP's `idx_const_close_v2`/`idx_const_o
pen_v2`
tables, which carry an `index_weight` field) lives under the
`crsp_q_mi_hist` physical schema, which this project's WRDS
subscription
tier does not grant `USAGE` on. `dsp500list_v2`/`msp500list_
v2` (the
membership tables this project uses — see `membership_interv
al_convention.md`
and `docs/data_notes/crsp_sp500_raw_pull_20260819.md`) carry
 membership
intervals only (`permno, indno, mbrstartdt, mbrenddt, mbrflg
, indfam`),
no weight column. See `docs/data_notes/crsp_sp500_raw_pull_2
0260819.md`
for the full access-path finding.

## Decision

Constituent weight is **self-computed from CRSP daily market
capitalization**, not sourced from a published S&P/CRSP inde
x-weight
field:

```
weight_i,t = dlycap_i,t / sum_{j in M_t} dlycap_j,t
```

where `dlycap_i,t` is CRSP's own daily market cap for permno
 `i` on date
`t` (`crsp_m_stock.dsf_v2.dlycap`, already pulled — see
`docs/data_notes/crsp_sp500_raw_pull_20260819.md`), and `M_t
` is the set
of permnos with an open membership interval at `t` per `dsp5
00list_v2`
(i.e. `mbrstartdt <= t < mbrenddt`, matching the half-open c
onvention in
`membership_interval_convention.md`). This is computed in
`src/universe/` at the point the CRSP membership and returns
 files are
merged into the canonical constituent panel — it is not part
 of the raw
pull.

## Why this is the right choice for this thesis, not just a
workaround

- **Standard in the concentration-measurement literature.**
Cap-weighted
  concentration measures (HHI, CR-k, effective-N — see
  `csi_construction.md`) are conventionally computed from co
nstituent
  market capitalization relative to total index market cap,
not from a
  vendor's published index weight, which additionally embeds
  index-methodology adjustments (float adjustment, foreign-o
wnership
  caps, cross-holding exclusions, IWF changes between rebala
nces) that
  are about *replicating the tradable index level*, not abou
t measuring
  *relative concentration structure*. Those adjustments are
immaterial to
  — and in some cases would actively distort — a state varia
ble meant to
  track how concentrated market value is among constituents.
- **Point-in-time by construction.** `dlycap_i,t = dlyprc_i,
t *
  shrout_i,t` as of date `t` alone; nothing about it depends
 on a value
  known only after `t`. This satisfies the CSI's anti-look-a
head
  requirement (`csi_construction.md`, "Anti-look-ahead rules
") without
  any extra handling.
- **No new access dependency.** Requesting `crsp_q_mi_hist`
access from
  WRDS is a separate administrative step with no guaranteed
outcome or
  timeline (see `docs/data_notes/crsp_sp500_raw_pull_2026081
9.md`); the
  self-computed weight uses data already pulled and availabl
e now.
- **Immaterial for this thesis's object of interest.** The C
SI compares
  *relative* concentration over time and across regimes (is
concentration
  rising, is it associated with elevated risk), not the exac
t published
  index level. A permno's self-computed weight and its offic
ially
  published weight will differ only at the margin (float-adj
ustment
  effects), and that margin is far smaller than the concentr
ation swings
  the CSI is designed to detect.

def apply_delisting_adjustment(
    returns: pd.DataFrame, delistings: pd.DataFrame
) -> tuple[pd.DataFrame, list[int]]:
    """Compound or append the delisting return per CRSP's d
ocumented
    convention. Returns the adjusted frame and the list of
permnos whose
    delret was missing (left unadjusted).
    """
    returns = returns.sort_values(["permno", "dlycaldt"]).r
eset_index(drop=True)
    last_obs_idx = returns.groupby("permno")["dlycaldt"].id
xmax()
    last_obs = returns.loc[last_obs_idx, ["permno", "dlycal
dt"]].rename(
        columns={"dlycaldt": "last_date"}
    )

    delist = delistings[["permno", "delistingdt", "delret",
 "delretmisstype"]].merge(
        last_obs, on="permno", how="left"
    )

    missing_delret = delist.loc[delist["delret"].isna(), "p
ermno"].tolist()
    delist = delist.dropna(subset=["delret"])

    compound_mask = delist["delistingdt"] == delist["last_d
ate"]
    append_mask = delist["delistingdt"] > delist["last_date
"]
    stale_mask = delist["delistingdt"] < delist["last_date"
]

    n_compound = int(compound_mask.sum())
    n_append = int(append_mask.sum())
    n_stale = int(stale_mask.sum())

    if n_stale:
        logger.warning(
            "%d delisting events have a delistingdt BEFORE
the permno's last "
            "regular return observation — left unadjusted,
flagged for review: %s",
            n_stale,
            delist.loc[stale_mask, "permno"].tolist(),
        )

    # Compound: same-date delisting return folds into the e
xisting row.
    compound_rows = delist.loc[compound_mask, ["permno", "d
elistingdt", "delret"]]
    for _, row in compound_rows.iterrows():
        idx = returns.index[
            (returns["permno"] == row["permno"]) & (returns
["dlycaldt"] == row["delistingdt"])
        ]
        returns.loc[idx, "dlyret"] = (1 + returns.loc[idx,
"dlyret"]) * (1 + row["delret"]) - 1

    # Append: delisting return becomes a new final observat
ion. dlycap is
    # left NaN (no market cap observation exists on a date
with no regular
    # trading) — downstream weight computation naturally ex
cludes it.
    append_rows = delist.loc[append_mask, ["permno", "delis
tingdt", "delret"]]
    if len(append_rows):
        new_rows = pd.DataFrame(
            {
                "permno": append_rows["permno"].to_numpy(),
                "dlycaldt": append_rows["delistingdt"].to_n
umpy(),
                "dlyret": append_rows["delret"].to_numpy(),
                "dlycap": float("nan"),
            }
        )
        returns = pd.concat([returns, new_rows], ignore_ind
ex=True)

    logger.info(
        "Delisting adjustment: %d compounded into last obse
rvation, %d appended as "
        "a new final observation, %d missing delret left un
adjusted (permnos: %s)",
        n_compound,
        n_append,
        len(missing_delret),
        missing_delret,
    )

    return returns.sort_values(["permno", "dlycaldt"]).rese
t_index(drop=True), missing_delret

Ragionamento: Theil grezzo vs. normalizzato

1) Sensibilità a N_t che varia (496-505 nel nostro universo)

Il termine ln(N_t) nel Theil grezzo introduce uno shift di livello meccanico ogni volta che N_t cambia — e questo accade indipendentemente dal comportamento reale della distribuzione dei pesi: un nome in coda con peso quasi-zero che entra/esce sposta ln(N_t) di Δln(N) senza che H_t si muova quasi per nulla (un peso vicino a zero contribuisce pochissimo a -Σw ln w). Su ln(496)→ln(505) lo shift è ~0.019 nats — piccolo in assoluto, ma un livello shift puro artefatto, non segnale.

Nella versione normalizzata T_norm = (ln N - H)/ln N, N_t compare sia a numeratore che denominatore: quando ricalcolo la derivata rispetto a N tenendo H pressoché fisso, l'effetto si cancella parzialmente (l'ordine di grandezza scende a ~0.2-0.3% dell'intero range [0,1], contro ~0.6-2% del range tipico della versione grezza). Normalizzare non elimina il rumore, ma lo attenua proporzionalmente.

Un punto rilevante per il nostro caso specifico: la variazione di N_t in questo panel non è vera dinamica economica dell'indice (l'S&P 500 è sempre ~500 nomi per costruzione) — è quasi certamente un artefatto del filtro sharetype/exchange e del pull a snapshot mensile. Questo rafforza l'argomento contro la versione grezza: non vogliamo che una misura pensata per catturare "dispersione della coda" sia in parte guidata da rumore della nostra pipeline di filtraggio.

2) Uso a valle — collinearity check e aggregazione

HHI, CR-k ed Effective N sono per costruzione immuni a N_t (dipendono solo dai pesi grandi/dai nomi top-k, non dal conteggio totale dei nomi in coda). Il Theil grezzo è l'unica delle 4 candidate a reintrodurre un canale di rumore che nessuna delle altre tre condivide. Questo è un problema specifico per il collinearity check: se entropy_concentration risultasse meno correlata con HHI/CR-k, non sapremmo dire se è perché cattura genuinamente la forma della coda (il motivo per cui l'abbiamo inclusa) o perché sta solo assorbendo rumore di composizione. La normalizzazione rimuove la maggior parte di questo canale spurio, rendendo un'eventuale divergenza da HHI più interpretabile come segnale genuino.

Per l'aggregazione (z-score average, Option B): lo z-scoring standardizza scala e livello, ma non cancella un rumore che varia nel tempo insieme al segnale vero — quindi l'argomento sopra si trasferisce quasi identico alla fase di aggregazione. Per PCA (Option C) la differenza è ininfluente, dato che entrambe le versioni vengono comunque standardizzate prima del fit.

3) Precedenti in letteratura

L'indice di Theil grezzo (T = Σ s_i ln(N s_i)) è la forma classica usata in IO industriale quando N è sostanzialmente costante nel campione (Theil 1967; Horowitz & Horowitz 1968 sul settore birrario). Ma la letteratura che si occupa esplicitamente di N che varia — che è proprio il nostro caso, solo in serie storica invece che cross-section — normalizza sistematicamente per ln(N) per rendere l'indice comparabile: Jacquemin & Berry (1979) sull'indice di entropia della diversificazione fa esattamente questo. C'è inoltre un parallelo diretto e molto standard fuori dalla finanza: 1 - H/ln(N) è l'esatto complemento a 1 dell'indice di evenness di Pielou (J = H/ln(S)), ampiamente usato in ecologia/biodiversità per confrontare comunità con numero di specie diverso — stesso identico problema statistico del nostro N_t che oscilla. Questo mi sembra il precedente più pertinente, più che la forma grezza da manuale IO con N fisso.

4) Downside della normalizzazione

- Instabilità numerica per N piccolo (denominatore ln(N)→0): non è un problema pratico qui, N~500 → ln(N)≈6.2, lontanissimo da zero.
- Perdita dell'interpretazione in "nats" (unità di informazione naturale, con lettura come divergenza KL dalla distribuzione uniforme): reale ma minore per gli scopi della tesi — un valore in [0,1] leggibile come "percentuale della concentrazione massima possibile" è probabilmente più immediato da esporre in sede di discussione che "X nats di scostamento."
- Non introduce comparabilità di scala con HHI/CR-k (che restano su scale naturalmente diverse, 0.01-0.05 vs 0.1-0.4) — quella comparabilità arriva comunque dallo z-scoring in fase di aggregazione, quindi non è un argomento decisivo né a favore né contro.

## Formula

**Normalized Shannon entropy, complemented so higher = more c
oncentrated:**

```
H_t = -Σ_i weight_i,t * ln(weight_i,t)      (Shannon entropy,
 nats)
entropy_concentration_t = 1 - H_t / ln(N_t)
```

where `N_t` is the number of active constituents at `t`. Equi
valently,
`entropy_concentration_t` is one minus **Pielou's evenness in
dex**
(ecology) applied to constituent weights, and is the *normali
zed* form of
the **Theil entropy index** for market concentration
(`T_t = ln(N_t) - H_t = Σ_i weight_i,t * ln(N_t * weight_i,t)
`, standard
in industrial-organization literature) — `entropy_concentrati
on_t =
T_t / ln(N_t)`.

- **Range:** `[0, 1]` — 0 at perfectly equal weights, 1 at si
ngle-name
  concentration.
- **Direction:** ↑ = more concentrated (`concentration_direct
ion("entropy_concentration") == +1`,
  no sign flip needed for aggregation).

## Why normalized rather than raw Theil (`ln(N_t) - H_t`)

Decided against the unnormalized Theil index specifically bec
ause `N_t`
(active constituent count) is not perfectly constant in this
project's
CRSP-sourced panel (~489-502 across the 2000-2026 build, see
`data_final/concentration/concentration_measures_monthly_<dat
e>.csv`) —
almost certainly a filtering/pull artifact (the share-type/ex
change filter
in `src/crsp/clean_sp500_raw.py`, monthly snapshot granularit
y), not
genuine index-composition churn. Raw Theil's `ln(N_t)` term s
hifts
mechanically whenever a near-zero-weight tail name enters or
leaves the
panel, independent of any real change in how weight is distri
buted
(`H_t` barely moves when a ~0-weight name is added/dropped, b
ut `ln(N_t)`
does). Since this measure's whole purpose is to be one of fou
r inputs to
a collinearity check against `hhi`/`cr_k` (none of which are
perturbed by
tail-name count at all) and a future composite aggregation, c
ontaminating
it with `N_t`-churn noise the other three don't share would m
ake any
observed distinctness from HHI hard to interpret — is it genu
ine
tail-shape signal, or just composition-count noise? Normalizi
ng by
`ln(N_t)` largely cancels this artifact (the two `N_t`-depend
ent terms
move together), at the cost of losing the literal "nats" unit
s — judged
an acceptable trade for a [0,1] concentration score that's al
so easier to
present. See the discussion in the phase-2 planning session
(2026-08-20) for the full reasoning (N_t-sensitivity magnitud

precedent in Jacquemin & Berry 1979 and Pielou's evenness ind

Conclusione: effective_n non va incluso come componente separato nel composito, indipendentemente dal numero grezzo sulle differenze — includerlo insieme a HHI significherebbe pesare due volte la stessa informazione, con un peso relativo che varia implicitamente nel campione a seconda del livello di HHI (di più quando HHI è basso, per via della curvatura di 1/x). Resta comunque utile come diagnostica riportata nell'output — la sua interpretazione "numero equivalente di titoli equal-weight" è più intuitiva di HHI grezzo per un lettore non tecnico — semplicemente non come input del composito.

4. Equal-weight z-score vs. PCA

Il rischio che segnali è reale ma si annida nella selezione, non nella formula di pesatura. Se si buttano tutti e 6 (o anche solo i 3 CR-k insieme) in uno z-score equal-weight senza prima curare l'insieme, il blocco CR-k (correlato 0.91-0.95 al suo interno anche sulle differenze) agisce di fatto come un unico mega-componente con peso triplo, diluendo entropy a 1/6 del totale — esattamente il problema che temi. Ma PCA non risolve questo automaticamente: la prima componente principale massimizza la varianza spiegata, quindi si orienterebbe comunque verso il blocco ridondante (che contribuisce più varianza condivisa) a scapito di entropy, a meno di curare l'input anche lì. È coerente con quanto csi_construction.md già segnala su Option C ("con ~5 misure la prima PC può essere instabile") — ora ne abbiamo la controprova empirica diretta.

Con un insieme già curato a 3 componenti (Combo B: uno per famiglia), il problema è in gran parte risolto a monte dalla selezione — a quel punto equal-weight z-score è la scelta più semplice, trasparente e coerente con la preferenza di csi_construction.md per la semplicità nel primo passaggio ("build Option A/B simplest first, defer PCA"). Raccomando equal-weight sul set curato come costruzione primaria, con PCA sullo stesso set curato riportato solo come robustness in Fase 6 — non come alternativa da decidere ora.

Combo B: hhi + cr_10 + entropy_concentration, pesatura equal-weight su z-score (finestra trailing/expanding per il point-in-time), effective_n escluso dal composito ma mantenuto come diagnostica riportata, PCA sullo stesso terzetto come robustness di Fase 6. Propongo terzili (33°/67° percentile) → 3 regimi (bassa/media/alta concentrazione) come default, non uno split mediano a 2 né soglie asimmetriche tipo 20°/80°.

Motivazione: uno split a 2 (mediana) è il più semplice e massimizza la numerosità per regime, ma perde la capacità di distinguere "moderatamente elevato" da "estremo" — proprio la distinzione che serve per il tipo di domanda che la tesi pone (concentrazione realizzata/prezzata durante episodi di stress vs. normali). Soglie asimmetriche (20°/80°, isolando solo le code) presuppongono implicitamente che solo la coda alta interessi — ragionevole per l'inquadramento "rischio sistemico" del progetto, ma è un'assunzione che non vogliamo congelare ora, prima di aver visto come si comporta il CSI nelle regressioni di Fase 4/5 (magari anche la bassa concentrazione produce risultati P-vs-Q interessanti, es. sotto-prezzamento del rischio di coda in mercati frammentati). I terzili sono lo standard più comune in letteratura sui regimi di concentrazione/rischio sistemico, restano interpretabili, e non pre-impegnano la tesi su un'ipotesi asimmetrica. Documento median-split e soglie asimmetriche come varianti di robustness in Fase 6, stesso trattamento riservato a PCA/rolling-window/burn-in altrove.

2) Finestra: rolling, non expanding — e qui la scelta è diversa da quella del composito, di proposito

Hai ragione a chiedere una motivazione a sé. Per lo z-score del composito, la finestra doveva solo mettere le serie su scala comparabile — la domanda economica era neutra rispetto a expanding vs rolling. Qui la domanda è "questo mese è insolito rispetto a cosa", e la risposta cambia sostanza a seconda della finestra:

- Expanding classificherebbe "alta concentrazione" rispetto a tutta la storia dal 2000. Dato il trend secolare forte già documentato, questo produrrebbe una lunga sequenza quasi ininterrotta di mesi "alta" da un certo punto in poi (2019+) — il regime finirebbe per essere quasi un proxy del tempo calendariale ("post-2019"), il che è un problema serio per una variabile che in Fase 4/6 deve condizionare regressioni: se "regime alto" collima quasi perfettamente con "dopo il 2019", diventa difficile isolare l'effetto marginale della concentrazione da qualunque altro fenomeno post-2019 (tassi, pandemia, ecc.) — esattamente il tipo di confondimento che il disegno P-vs-Q vuole evitare.
- Rolling (propongo 60 mesi, 5 anni) chiede invece "è insolito rispetto ai 5 anni recenti" — questo produce transizioni genuine avanti e indietro nel tempo (il regime può tornare "medio" anche dopo un lungo periodo "alto", se la concentrazione si stabilizza al nuovo livello), dando alla variabile la variazione temporale che serve per essere identificabile in una regressione, invece di essere quasi collineare con un trend temporale. Il costo: un parametro di lunghezza-finestra in più da giustificare (esattamente il tipo di scelta che avevamo evitato nel composito scegliendo expanding) e una perdita di burn-in più consistente (i primi 5 anni, 2000-2005, restano senza classificazione — non trascurabile ma accettabile su un campione di 26 anni).

Nota di coerenza interna: se in Fase 6 testeremo comunque una variante rolling da 60 mesi per il composito come robustness, riusare qui la stessa lunghezza evita di introdurre un terzo numero arbitrario nel documento.

3) Isteresi / flickering

Propongo nessuna isteresi nel primo passaggio — soglie grezze, classificazione diretta mese per mese — con una motivazione esplicita del limite noto (rischio di alternanza spuria tra regimi adiacenti in mesi consecutivi vicino a un cutoff), coerente con l'approccio "il più semplice prima" già seguito per aggregazione, PCA, burn-in. Aggiungerei però una cosa a basso costo: loggare un diagnostico del tasso di flickering (es. quante transizioni "andata e ritorno" in ≤2 mesi si osservano nella serie effettiva) quando costruisco la classificazione — così, invece di indovinare se serve isteresi, lo vediamo empiricamente prima di decidere se vale la pena costruirla in Fase 6 (banda di isteresi, durata minima, o il modello Markov-switching già previsto come alternativa più complessa nel documento). Stesso principio già usato per la soglia di collinearità: calcola prima, decidi la complessità dopo aver visto il dato reale.

def classify_regime(csi: pd.DataFrame, window: int = ROLLING

    df["rolling_p33"] = roll.quantile(LOWER_PCT)
